# Aura 部署打包指引

## 概述

项目有两个打包脚本，均在 `deploy/` 目录下：

| 脚本 | 产物 | 用途 |
|------|------|------|
| `build-server-lan.bat` | `bin/aura-server/` | 内网 Windows 服务端部署包 |
| `build-client-lan.bat` | `bin/aura-client/` | 内网 Windows 桌面客户端（Tauri） |

先打服务端，拿到服务器 IP 后再打客户端（客户端需要知道连谁）。

---

## 一、数据库初始化（首次部署或 Schema 变更后必须执行）

Aura 使用 **Drizzle ORM** 管理数据库 Schema，迁移文件位于 `web-aura-next/drizzle/` 目录（`0000_*.sql` ~ `0005_*.sql`）。

### 什么时候需要执行

| 场景 | 是否需要迁移 |
|------|:--:|
| 首次部署（全新数据库） | ✅ 必须 |
| 代码更新且新增了 `drizzle/*.sql` 迁移文件 | ✅ 必须 |
| 仅更新业务代码，无 Schema 变更 | ❌ 不需要 |

### 迁移做了什么

部署包中已内置 `src/lib/db/migrate.cjs`，执行时会按顺序：

1. **启用 pgvector 扩展** — `CREATE EXTENSION IF NOT EXISTS vector`
2. **应用未执行的 SQL 迁移** — 创建/更新 `users`、`workspaces`、`chat_messages`、`agent_knowledge`、`workspace_runs`、`run_steps`、`scene_definitions`、`db_connections`、`workspace_memories`、`user_settings`、`user_model_configs` 等表

### 执行方式

部署包中已内置 `src/lib/db/migrate.cjs`（纯 JS，所有依赖均为生产依赖，无需 `tsx`）：

```bash
cd D:\app\aura-server
node src/lib/db/migrate.cjs
```

> **注意**：执行迁移前需确保 `.env` 中 `DATABASE_URL` 指向正确的数据库。

## 二、服务端打包 `build-server-lan.bat`

### 配置入口：脚本头部变量

编辑 `deploy/build-server-lan.bat` 第 13-19 行：

```batch
set "DB_HOST=localhost"          # PostgreSQL 数据库 IP
set "DB_PORT=5432"               # 数据库端口
set "DB_USER=root"               # 数据库用户名
set "DB_PASSWORD=root"           # 数据库密码
set "DB_NAME=aura_db"            # 数据库名
set "SERVER_PORT=8086"           # 服务监听端口
set "DEPLOY_DIR=D:\app\aura-server"  # 生产环境部署目录
```

服务端**不需要配 IP 地址**——它监听 `0.0.0.0:SERVER_PORT`，对外暴露的是部署机器自身 IP。

### 额外依赖：`web-aura-next/.env.local`

构建时 `npm run build`（Next.js standalone 模式）会读取此文件，以下变量会被编入构建产物：

| 变量 | 说明 |
|------|------|
| `DEEPSEEK_API_KEY` | DeepSeek API 密钥（必填） |
| `DEEPSEEK_BASE_URL` | DeepSeek API 地址 |
| `AURA_ENCRYPTION_KEY` | AES-256-GCM 加密密钥，用于加密存储敏感数据（必填） |
| `DATABASE_URL` | 开发用数据库连接（生产由 `.env` 覆盖） |

### 配置链路

```
build-server-lan.bat 头部变量
        │
        ├──→ 注入 npm run build（Next.js standalone）
        │        └── 读取 .env.local → DEEPSEEK_API_KEY / AURA_ENCRYPTION_KEY
        │
        ├──→ 生成 bin/aura-server/.env（DATABASE_URL + PORT + NODE_ENV）
        └──→ 生成 bin/aura-server/AuraServer.xml（WinSW 服务定义）
```

### 产物结构

```
bin/aura-server/
├── server.js              # Next.js Standalone 入口
├── .next/                 # 编译产物
├── node_modules/          # 生产依赖
├── public/                # 静态资源
├── src/                   # API 路由源文件 + migrate.cjs
├── drizzle/               # 数据库迁移 SQL 文件
├── .env                   # 运行时环境变量（DATABASE_URL / PORT）
├── AuraServer.xml         # WinSW 服务定义
└── AuraServer.exe         # WinSW 可执行文件
```

## 三、客户端打包 `build-client-lan.bat`

### 配置入口：`web-aura-next/.env.lan`

```env
# 运行模式：client = 客户端模式（通过 X-Aura-Local-Key 免登接入服务端）
AURA_MODE=client

# ⚠️ 这里必须改成服务端实际 IP:端口
AURA_SERVER_URL=http://localhost:8086
```

### 配置如何生效

```
.env.lan
    │
    └── next.config.ts (env 字段)
            │
            └── 构建时内联进 JS bundle
                    │
                    └── Tauri 壳启动 Next.js → 客户端直接使用 AURA_SERVER_URL 连接服务端
```

`build-client-lan.bat` 会：
1. 读取 `.env.lan` 并注入当前进程环境变量
2. 执行 `npm run tauri build`（内部先 `next build`，再 `tauri build`）
3. Next.js 构建时通过 `next.config.ts` 的 `env` 字段将 `AURA_MODE` / `AURA_SERVER_URL` 内联到客户端 JS bundle
4. Tauri 编译 Rust 桌面壳，打包为 exe / msi

### 产物结构

```
bin/aura-client/
├── aura-client.exe        # 绿色免安装版
├── Aura_*.msi             # MSI 安装包
└── Aura_*-setup.exe       # NSIS 安装引导程序
```

## 四、打包前确认清单

### 服务端

| # | 检查项 | 位置 |
|:--:|------|------|
| 1 | 数据库已启动且可连通（PostgreSQL + pgvector） | — |
| 2 | 数据库迁移已执行（首次部署 / Schema 变更后） | 参照"一、数据库初始化" |
| 3 | 数据库 IP、端口、账号、密码正确 | `build-server-lan.bat` 头部 |
| 4 | DeepSeek API Key 有效 | `web-aura-next/.env.local` |
| 5 | `AURA_ENCRYPTION_KEY` 已配置 | `web-aura-next/.env.local` |
| 6 | 服务端口未被占用（默认 8086） | `build-server-lan.bat` 头部 |

### 客户端

| # | 检查项 | 位置 |
|:--:|------|------|
| 1 | `AURA_MODE=client` | `web-aura-next/.env.lan` |
| 2 | `AURA_SERVER_URL` 指向正确的服务端 IP:端口 | `web-aura-next/.env.lan` |

## 五、典型部署流程

```
1. 确认 PostgreSQL 数据库已启动且可连通
2. 编辑 build-server-lan.bat 头部 → 数据库连接参数
3. 确认 .env.local → DEEPSEEK_API_KEY / AURA_ENCRYPTION_KEY
4. 运行 build-server-lan.bat → 生成 bin/aura-server/
5. 将 bin/aura-server/ 下所有文件复制到目标服务器 D:\app\aura-server\
6. 以管理员身份打开 cmd，进入部署目录：
      cd /d D:\app\aura-server
7. 【首次部署/表结构变更时】执行数据库迁移：
      node src/lib/db/migrate.cjs
8. 安装并启动 Windows 服务：
      AuraServer.exe install
      AuraServer.exe start
9. 验证：浏览器访问 http://<服务器IP>:8086
10. 编辑 .env.lan → AURA_SERVER_URL=http://<服务器IP>:8086
11. 运行 build-client-lan.bat → 生成 bin/aura-client/
12. 分发客户端安装包给用户
```

### WinSW 服务管理命令

所有操作需在部署目录 `D:\app\aura-server` 下**以管理员身份**执行：

| 操作 | 命令 |
|------|------|
| 安装服务 | `AuraServer.exe install` |
| 启动服务 | `AuraServer.exe start` |
| 停止服务 | `AuraServer.exe stop` |
| 重启服务 | `AuraServer.exe restart` |
| 查看状态 | `AuraServer.exe status` |
| 刷新配置 | `AuraServer.exe refresh` |
| 卸载服务 | `AuraServer.exe uninstall` |

**日志位置：**
- 服务管理日志：`AuraServer.wrapper.log`
- 应用标准输出：`AuraServer.out.log`
- 应用错误输出：`AuraServer.err.log`
