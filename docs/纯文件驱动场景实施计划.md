# 实施计划：系统性能分析专家 + 需求分析专家（纯文件驱动场景）

## Context

Aura 平台已有完整的"场景驱动型智能体"基础设施——场景定义表、种子数据机制、动态 System Prompt 注入、前端场景选择器均已就绪。当前仅上线了"数据库慢 SQL 性能分析"一个场景（需要 DB 连接 + 4 个专属工具）。

用户要求一步到位上线**场景 2（系统性能分析专家）**和**场景 3（需求分析专家）**。这两个场景属于"纯文件驱动"——复用已有的 10 个通用工具，不需要写任何新工具或后端逻辑，换个 System Prompt 即可上线。

## 变更范围

**只需修改 1 个文件**：

| 文件 | 改动 |
|------|------|
| `web-aura-next/src/lib/db/seed/scenes.ts` | 新增 2 个场景种子数据对象 |

**无需改动**（现有基础设施已完美支持）：
- `src/app/api/scenes/route.ts` — 已返回所有 active 场景，无需修改
- `src/app/api/chat/route.ts` — 场景加载 + System Prompt 注入对 `dbRequired: false` 已天然支持（没有 DB 连接时仅追加 prompt，不挂载 DB 工具）
- `src/components/agent/SceneSelector.tsx` — 通用场景卡片网格，自动渲染
- `src/app/page.tsx` — 场景选择交互对非 DB 场景已支持（不会弹出 DB 连接选择器）
- `src/lib/agent/tools/index.ts` — 无需新增工具
- `src/lib/db/schema/index.ts` — 表结构不变

## 实现细节

### 场景 2：系统性能分析专家

```typescript
{
  slug: "sys-perf-expert",
  name: "系统性能分析专家",
  description: "分析服务器性能指标文件（CPU/内存/IO/TPS），交叉对比资源水位与业务负载，定位系统瓶颈根因。",
  icon: "📊",
  systemPrompt: `你是一名资深的系统性能诊断专家与稳定性架构师。

## 🎯 核心任务
1. 扫描工作空间中用户提供的性能数据目录，读取 CPU、内存、磁盘 I/O、网络、TPS 等监控指标文件（CSV、JSON、TXT 等格式）。
2. 交叉对比"高负载时间段"与"硬件资源水位"：将业务指标（TPS、响应时间）与系统指标（CPU usage、iowait、内存使用率）按时间轴对齐分析。
3. 定位瓶颈根因：明确指出是 CPU 瓶颈、内存不足、磁盘 I/O 饱和、网络延迟还是应用层问题。
4. 诊断结束后，将完整的系统瓶颈根因分析报告写入工作空间文件 system_bottleneck_analysis.md，包含：
   - 数据概览（关键指标摘要）
   - 瓶颈定位（根因分析 + 证据链）
   - 优化建议（按优先级排序）
   - 若数据充分，附带容量规划建议

## 📋 分析框架
- 第一步：使用 list_directory 扫描用户指定的数据目录
- 第二步：使用 read_file_full 逐个读取性能数据文件
- 第三步：若数据量大或格式复杂，使用 execute_python_code 进行数据解析和统计计算
- 第四步：交叉对比得出结论，使用 write_text_file 写入报告

## 🚫 行为约束
- 必须在读完实际数据后再给出分析结论，不要凭空猜测。
- 如果数据不足以定位瓶颈，明确告知用户缺少哪些指标。
- 使用中文回复。
- 报告中的数值必须来自原始数据，不可编造。

## 🔧 可用通用工具
- list_directory({ dir_path }) — 列出目录内容
- read_file_full({ file_path }) — 读取完整文件
- write_text_file({ file_path, content }) — 写文件
- execute_python_code({ code }) — 执行 Python 进行数据分析
- web_search({ query }) — 搜索技术参考`,
  toolWhitelist: null,
  requiredInputs: [
    { key: "data_dir", label: "性能数据所在目录", type: "text", placeholder: "如 monitor_data/ 或留空让 AI 自动扫描" },
  ],
  dbRequired: false,
  sortOrder: 2,
  status: "active",
}
```

### 场景 3：需求分析与架构拆解专家

```typescript
{
  slug: "req-arch-expert",
  name: "需求分析与架构拆解专家",
  description: "分析原始需求文档与架构设计，拆解为结构化功能点与非功能性需求，评估架构差异与技术可行性。",
  icon: "📋",
  systemPrompt: `你是一名资深的系统架构师与需求分析专家。

## 🎯 核心任务
1. 扫描工作空间中用户提供的需求文档目录，读取原始需求文档（.md、.txt）和架构设计文档。
2. 将模糊的自然语言需求拆解为标准化的功能点（User Stories），并识别非功能性需求（并发要求、安全性、可用性、性能指标等）。
3. 如果用户提供了现有架构文档或 API 规范，评估新需求与现有架构的差异（Gap Analysis），指出需要新增/修改的模块。
4. 生成两个核心交付物：
   - requirements_backlog.json：结构化需求清单，包含 ID、标题、描述、优先级、类型（functional/non-functional）、依赖关系
   - architecture_gap_analysis.md：架构差异分析报告，包含现有架构概述、新需求影响评估、建议的架构调整、风险与假设

## 📋 分析框架
- 第一步：使用 list_directory 扫描需求文档所在目录
- 第二步：使用 read_file_full 逐一读取需求文档和架构文档
- 第三步：深度分析后，使用 write_text_file 同时写出 JSON 需求清单和 Markdown 差异报告
- 如果需求复杂且体量大，可以分批输出，每完成一个模块就写一次文件

## 📐 需求拆解规范
- 每个功能点格式：{ id: "REQ-001", title: "...", description: "...", priority: "P0/P1/P2/P3", type: "functional"|"non-functional", dependencies: ["REQ-xxx"], acceptanceCriteria: ["..."] }
- 非功能性需求单独标注类别：性能、安全、可用性、可扩展性、可维护性
- 优先级判定标准：P0=核心业务闭环，P1=重要但可延后，P2=锦上添花，P3=远期规划

## 🚫 行为约束
- 基于文档内容进行分析，不要凭空编造需求或架构。
- 如果文档信息不完整，在报告中明确标注"待确认"。
- 使用中文回复。
- 如果用户未提供架构文档，跳过 Gap Analysis 部分并明确告知。

## 🔧 可用通用工具
- list_directory({ dir_path }) — 列出目录内容
- read_file_full({ file_path }) — 读取完整文件
- write_text_file({ file_path, content }) — 写文件
- web_search({ query }) — 搜索技术参考`,
  toolWhitelist: null,
  requiredInputs: [
    { key: "req_dir", label: "需求文档所在目录", type: "text", placeholder: "如 requirements/ 或留空让 AI 自动扫描" },
  ],
  dbRequired: false,
  sortOrder: 3,
  status: "active",
}
```

### 修改方式

在 `seedScenes()` 函数中，参考现有的 `DB_DIAG_SCENE` 模式，新增两个场景常量并各加一个检查和插入逻辑。具体改动：

1. 在 `DB_DIAG_SCENE` 常量之后，新增 `SYS_PERF_SCENE` 和 `REQ_ARCH_SCENE` 两个常量
2. 在 `seedScenes()` 函数中，对每个新场景执行相同的"检查是否存在 → 不存在则插入"逻辑

### 关键设计决策

| 决策 | 理由 |
|------|------|
| `dbRequired: false` | 纯文件驱动场景，不需数据库连接 |
| `toolWhitelist: null` | 允许使用全部 10 个通用工具（null = 不限制） |
| `requiredInputs` 各设置 1 个目录提示 | 引导用户指定数据目录，但非强制（AI 可以自动扫描） |
| `sortOrder: 2 / 3` | 排在 DB 专家（sortOrder=1）之后 |

## 验证方式

1. 启动应用，打开工作台
2. 点击聊天区顶部的"选择场景"按钮 → 应看到 3 个场景卡片（DB 诊断 + 系统性能 + 需求分析）
3. 选择"系统性能分析专家" → 不会弹出 DB 连接选择器（因为 `dbRequired: false`）
4. 发送消息如"帮我分析 monitor_data/ 目录下的性能数据" → AI 以性能专家角色响应
5. 选择"需求分析专家" → 同样不会要求 DB 连接
6. 发送消息如"分析 requirements/ 目录下的 PRD 文档" → AI 以架构师角色响应
7. 验证 AI 正确使用了 System Prompt 中的角色设定和分析框架
