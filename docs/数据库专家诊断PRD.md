## 1. 纠正一个误区：执行计划不需要 `root` (Superuser) 权限

这是一个常见的直觉误区，但从数据库底层的安全设计来看：**看执行计划，并不需要数据库的 root / superuser 权限。**

在 PostgreSQL 或 MySQL 中，权限逻辑是这样的：

* **原则：** 只要这个数据库用户**有权限执行这条 SQL**（比如对相关的表有 `SELECT` 权限），那么它就**自动拥有**查看这条 SQL 执行计划（`EXPLAIN`）的权限。
* **例外情况（`EXPLAIN ANALYZE`）：** 如果你使用 `EXPLAIN ANALYZE`，数据库会真实地把这条 SQL 跑一遍来获取实际耗时。因此，对于 `SELECT` 语句，只要有读权限就能跑；但如果是测试一条慢 `UPDATE` 或 `DELETE`，执行它的用户就必须拥有写权限。
* **智能体需要的最低权限：**
* 对业务表拥有 `SELECT` 权限（用来跑 `EXPLAIN`）。
* 如果需要智能体自动去系统视图（如 PG 的 `pg_stat_statements`）里抓取最近的慢 SQL 列表，你只需要把这个系统视图的 `SELECT` 权限赋予该用户即可，**绝对不需要给 Root 账号**。

## 4. 实验环境下的关键防线（防 AI 踩坑）

既然你在实验环境下“全权交给智能体”，有两点好玩的、也是 Agent 容易踩的坑，你可以在 System Prompt 里提前给它打预防针：

* **防范 `EXPLAIN ANALYZE` 的修改副作用：**
如果慢 SQL 是一条 `DELETE FROM users WHERE ...`，一旦 Agent 盲目运行 `EXPLAIN ANALYZE DELETE...`，这条数据在实验环境里就**真的被删掉了**。
* *优化提示：* 可以在系统提示词里规定：“*如果你要分析带有写操作的 SQL，必须先在工具里包裹 `BEGIN; EXPLAIN ANALYZE ...; ROLLBACK;` 事务，绝对不能真实污染数据库。*”


* **防止大表死锁：**
在实验环境数据量很大时，`EXPLAIN ANALYZE` 可能会让大模型把一条本就很慢的查询再跑一遍，导致后台连接池被占满。

## 二、 核心疑问深度剖析与落地设计

### 1. 数据库连接配置，是不是还需要有地方专门录入？

**答案：是的，最佳实践是提供“显式表单录入”与“隐式文件解析”的双轨制。**

* **方案 A（显式录入 - 体验最好）：**
在前端点击加号选择“数据库诊断专家”时，聊天框上方弹出一个轻量级的 **“连接配置卡片”**，要求输入 Host、Port、DBName、User、Password。
* *数据流向*：用户点击保存后，前端将这组数据加密，在发起聊天请求时，作为 `metadata` 或者是 `options` 随请求一起发送给后端。后端在本次会话的上下文中**动态创建数据库连接池**。


* **方案 B（隐式解析 - 极客首选）：**
正如你之前提到的，用户可以直接在输入框说：“凭证在工作空间根目录的 `.env` 文件里”。
* *数据流向*：此时不需要专属 UI。智能体的第一步思考会驱使它调用通用基础工具中的 `readFile('.env')`，在服务端内存中用正则解析出连接串。



> 💡 **架构建议**：对于通用平台，**优先做方案 A（表单录入）**。因为让大模型去读各种奇形怪状的配置文件，很容易因为格式问题（比如多了一个引号、密码带特殊字符）导致解析失败，表单录入能保证 100% 的连接成功率。

### 2. 连数据库，是不是还要专门写工具（Tools）？

**答案：必须专门写。通用基础工具只能帮你“连上服务器的 Shell”，而数据库工具是智能体的“专业化听诊器”。**

你需要在后端为这个专家角色注入一组**高内聚、只读安全**的数据库工具集（Database SDK Tools）：

* **`db_execute_query`（通用只读查询工具）：**
* *逻辑*：接收一条 SQL，在连接池中执行，返回结构化 JSON。
* *约束*：后端必须做严格的 AST（抽象语法树）解析或正则拦截，**只允许执行 `SELECT` 或 `SHOW` 语句**，严禁 `DROP/UPDATE/DELETE`。


* **`db_get_execution_plan`（执行计划工具）：**
* *逻辑*：接收一条 SQL，后端自动在前面拼接 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`，然后发给数据库执行，把完整的 JSON 树返回给大模型。


* **`db_get_table_metadata`（元数据工具）：**
* *逻辑*：接收表名，查询系统元数据表，返回该表的所有字段类型、当前已有的索引名称、索引字段。
