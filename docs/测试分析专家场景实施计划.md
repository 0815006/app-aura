## 一、场景概述

### 1.1 场景定位

在银行系统研发流程中，**测试分析专家（bank-test-analyser）** 处于"承上启下"的关键环节——它将上游功能点估算专家数出来的需求、接口和企业标准，**真正变成能够落地执行的"测试兵器库"**。

该场景负责：
- 读取功能点明细表和需求设计文档，梳理测试接口清单与状态流转矩阵
- 依据金融级测试设计方法论，穷举正向交易、异常流、逆向交易用例
- 自动生成符合银行内审标准的 Excel 测试用例集
- 导出批量造数规则 JSON，供下游"批量文件造数专家"直读

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| 测试矩阵提取 | 从功能点明细中提取接口清单、核心检查点、状态机图谱 |
| 正向用例设计 | 正常记账、多账户并发记账等 Happy Path |
| 逆向用例设计 | 超时冲正、冲正失败挂账、冲减、撤销等银行特有逆向交易 |
| 异常边界用例 | 金额为0/负数/溢出、账户冻结/销户状态、重复提交幂等校验 |
| 非功能用例 | 网络延迟模拟、断线重连、分布式锁超时竞争（跨地域联调场景） |
| Excel 用例生成 | 自动生成符合银行合规内审标准的 `.xlsx` 测试用例文件 |
| 造数规则导出 | 生成字段类型、边界值、脱敏策略的结构化 JSON，供下游造数工具直读 |

### 1.3 场景特征

- **类型**: 纯文件驱动场景（与"功能点估算专家"同类）
- **DB 依赖**: 无（不需要数据库连接）
- **新工具**: 不需要（复用现有文件读写 + Excel 生成工具 + Agent 内置金融测试知识）
- **输入**: 
  - 工作空间 `inputs/` 目录下的需求文档和设计文档
  - 上游产出 `outputs/estimations/02_功能点明细表.json`（可选但推荐）
- **输出**: `outputs/test-analysis/` 目录下的 Markdown 报告 + Excel 用例 + JSON 造数规则

### 4.2 银行特有逆向交易知识库（嵌入 Prompt）

| 交易类型 | 说明 | 测试要点 |
|---------|------|---------|
| **冲正 (Reversal)** | 当日交易撤销，恢复账户余额 | 超时自动冲正、手动冲正、冲正幂等 |
| **冲减 (Offset)** | 跨日账务调整，不恢复原交易 | 冲减金额大于原交易、部分冲减 |
| **撤销 (Cancel)** | 未清算交易的取消 | 已清算后撤销应失败、撤销幂等 |
| **超时冲正** | 长事务断线后自动触发 | 网络超时阈值、冲正时序、挂账处理 |
| **挂账 (Suspense)** | 冲正失败后的临时挂起 | 挂账解挂流程、超时告警 |

### 4.3 金融测试设计方法论（嵌入 Prompt）

**等价类划分法**：
- 有效等价类：正常金额范围（如 0.01 ~ 999,999,999.99）
- 无效等价类：金额为 0、负数、超过限额、非数值

**边界值分析法**：
- 金额边界：0.00、0.01、MAX_AMOUNT、MAX_AMOUNT + 0.01
- 账户边界：正常、冻结、销户、未激活
- 并发边界：1 笔、N-1 笔、N 笔（最大并发）、N+1 笔

**状态迁移法**：
- 账户状态机：正常 ↔ 冻结 → 销户
- 交易状态机：待记账 → 锁存中 → 记账成功 / 超时→自动冲正
- 冲正状态机：待冲正 → 冲正中 → 冲正成功 / 冲正失败→挂账

**正交试验法**：
- 因子：交易类型 × 账户状态 × 金额区间 × 渠道类型
- 从全排列中按正交表选取代表性组合，减少用例数量同时保证覆盖率

## 六、风险与注意事项

1. **System Prompt 长度**: 金融测试方法论 + 逆向交易知识库 + 用例模板嵌入 Prompt 会增加 Token 消耗，估算约 +2500 tokens/次。对于测试分析这类专业场景，知识准确性优先于 Token 成本。
2. **LLM 逆向交易覆盖**: 大模型对银行特有的"冲正/冲减/挂账"等逆向交易概念可能不够深入。Prompt 中以知识库形式嵌入明确定义 + 测试要点，降低遗漏风险。
3. **跨场景联动**: 本场景依赖上游"功能点估算专家"的输出 `outputs/estimations/02_功能点明细表.json`。如果该文件不存在，Agent 需能从原始需求文档中自行提取测试目标。Prompt 中明确两种路径的 fallback 逻辑。
4. **Excel 用例生成**: 现有 `generate_structured_excel` 工具已支持多 Sheet 结构化写入，可将"正向/逆向/异常/性能"四类用例分为四个 Sheet，符合银行审计习惯。
5. **PRD 专属工具**: PRD 中提到的 `extract_test_matrix` / `generate_excel_test_cases` / `export_data_generation_rules` 三个专属工具，当前阶段通过 System Prompt + 现有通用工具覆盖。后续如需更高的生成精度（如强制 Excel 格式校验、字段级脱敏算法实现），可迭代为专属工具。
6. **后续迭代方向**: 
   - `extract_test_matrix` — 状态机自动可视化（Mermaid 图表生成）
   - `generate_excel_test_cases` — 支持银行自定义 Excel 模板上传与渲染
   - `export_data_generation_rules` — 对接 Python 批量造数脚本的直通执行
