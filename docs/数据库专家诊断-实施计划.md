## 需求概述

在 Aura 工作台中实现 **"数据库专家诊断"场景**，这是平台首个"场景驱动型智能体（Scenario-Driven Agent）"。核心思路：

1. 用户选择"数据库诊断专家"场景
2. 选择（或新建）一个已保存的数据库连接配置
3. 智能体以 DBA 角色运行，携带专用 DB 工具（`EXPLAIN`、查元数据、抓慢 SQL 等）
4. 自主完成慢 SQL 诊断 → 执行计划分析 → 优化方案生成 → 写入工作空间

**关键额外要求**：数据库连接配置**独立存储到数据库表**，提供完整的 CRUD + 测试连接功能。

5. **无动态工具挂载** — 当前工具集是固定的 10 个通用工具，无法按场景动态启用

## 二、数据库改造

### 2.1 新增表：`scene_definitions`

场景定义表，存储每个场景的结构化配置。MVP 阶段通过种子数据预置一个"数据库诊断专家"场景，后续可通过管理界面扩充。

```sql
CREATE TABLE scene_definitions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    slug            VARCHAR(100) NOT NULL UNIQUE,      -- 唯一标识，如 'db-slow-query-analyzer'
    name            VARCHAR(200) NOT NULL,              -- 显示名称
    description     TEXT,                               -- 场景描述
    icon            VARCHAR(50) DEFAULT '🔧',           -- emoji 图标
    system_prompt   TEXT NOT NULL,                      -- 场景专属 System Prompt 扩展
    tool_whitelist  JSONB DEFAULT '[]',                 -- 场景可用工具列表（null=全部通用工具 + 场景专属工具）
    required_inputs JSONB DEFAULT '[]',                 -- 入参表单提示 [{ key, label, type, placeholder }]
    db_required     BOOLEAN DEFAULT false,              -- 是否需要数据库连接（true=选择场景后必须选择 DB 连接）
    sort_order      INTEGER DEFAULT 0,                  -- 排序权重
    status          VARCHAR(20) DEFAULT 'active',        -- 'active' | 'archived'
    create_time     TIMESTAMPTZ DEFAULT NOW(),
    update_time     TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_scenes_status ON scene_definitions(status, sort_order);
```

### 2.2 新增表：`db_connections`

数据库连接配置表，用户可新增、修改、删除，并测试连通性。密码使用 AES-256-GCM 加密存储（与 `user_model_configs.api_key_encrypted` 一致）。

```sql
CREATE TABLE db_connections (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id           INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    label             VARCHAR(200) NOT NULL,             -- 用户自定义标签（如 "生产-PostgreSQL-只读"）
    db_type           VARCHAR(50) NOT NULL DEFAULT 'postgresql',  -- 'postgresql' | 'mysql'
    host              VARCHAR(255) NOT NULL,              -- 主机地址
    port              INTEGER NOT NULL,                   -- 端口（PG 默认 5432，MySQL 默认 3306）
    db_name           VARCHAR(255) NOT NULL,              -- 数据库名
    username          VARCHAR(255) NOT NULL,              -- 用户名
    password_encrypted TEXT NOT NULL,                     -- AES-256-GCM 加密后的密码
    ssl_mode          VARCHAR(50) DEFAULT 'prefer',       -- SSL 模式（PG: disable/allow/prefer/require; MySQL: true/false）
    extra_args        JSONB DEFAULT '{}',                 -- 额外连接参数（如 connect_timeout）
    last_tested_at    TIMESTAMPTZ,                        -- 最后一次测试连接时间
    test_result       VARCHAR(20),                        -- 'success' | 'failed'
    test_message      TEXT,                               -- 测试连接结果消息
    status            VARCHAR(20) DEFAULT 'active',        -- 'active' | 'archived'
    create_time       TIMESTAMPTZ DEFAULT NOW(),
    update_time       TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_db_conn_user ON db_connections(user_id, status);
CREATE UNIQUE INDEX uidx_db_conn_label ON db_connections(user_id, label);
```

## 三、后端 API 设计

### 3.1 场景 API

#### `GET /api/scenes` — 获取可用场景列表

```
Response: {
  code: 200,
  data: {
    scenes: [{
      id, slug, name, description, icon, dbRequired, sortOrder
    }]
  }
}
```

- 仅返回 `status = 'active'` 的场景
- 按 `sort_order` 升序排列
- 不返回 `system_prompt`（仅在选择具体场景时返回）

#### `GET /api/scenes/[slug]` — 获取场景详情

```
Response: {
  code: 200,
  data: {
    id, slug, name, description, icon,
    systemPrompt, toolWhitelist, requiredInputs, dbRequired
  }
}
```

### 3.2 数据库连接 API

#### `GET /api/db-connections` — 获取用户的数据库连接列表

```
Response: {
  code: 200,
  data: {
    connections: [{
      id, label, dbType, host, port, dbName, username,
      sslMode, lastTestedAt, testResult, testMessage,
      createTime, updateTime
    }]
  }
}
```

> **注意**：不返回 `passwordEncrypted`，密码仅在服务端解密使用。

#### `POST /api/db-connections` — 新增数据库连接

```
Body: { label, dbType, host, port, dbName, username, password, sslMode?, extraArgs? }
Response: { code: 201, data: { id, label, ... } }
```

- 密码在服务端使用 `encrypt()` 加密后存入 `password_encrypted`
- 校验 `label` 在同一用户下唯一
- 校验必填字段：`label`, `host`, `port`, `dbName`, `username`, `password`

#### `PUT /api/db-connections/[id]` — 修改数据库连接

```
Body: { label?, dbType?, host?, port?, dbName?, username?, password?, sslMode?, extraArgs? }
Response: { code: 200, data: { ... } }
```

- 如果 `password` 字段非空，重新加密更新；如果为空，保留原密码
- 校验 `label` 唯一性

#### `DELETE /api/db-connections/[id]` — 删除数据库连接

```
Response: { code: 200, message: "已删除" }
```

- 校验该连接属于当前用户

#### `POST /api/db-connections/[id]/test` — 测试数据库连接

```
Response (成功): { code: 200, data: { success: true, message: "连接成功 (PostgreSQL 16.2, 延迟 12ms)" } }
Response (失败): { code: 200, data: { success: false, message: "连接失败: Connection refused" } }
```

- 从 DB 读取连接配置，解密密码，尝试建立 TCP 连接 + 执行 `SELECT 1`
- 更新 `last_tested_at`、`test_result`、`test_message`
- 使用 `pg` (postgres) 或 `mysql2` 驱动，设置连接超时（5s）

### 3.3 Chat API 增强 (`POST /api/chat`)

现有 `/api/chat` 需增加场景感知能力：

#### 请求体新增字段

```typescript
{
  sceneSlug?: string;         // 场景标识，如 'db-slow-query-analyzer'
  dbConnectionId?: string;    // 数据库连接 ID（场景需要 DB 时必传）
  // ... 原有字段保持不变
```

#### 处理流程增强

```
POST /api/chat 处理流程（改造后）:

1. 解析 body.sceneSlug
   ├── 如果有 sceneSlug:
   │   ├── 从 scene_definitions 表加载场景配置
   │   ├── 将 scene.systemPrompt 追加到 system prompt
   │   ├── 如果 scene.dbRequired && body.dbConnectionId:
   │   │   ├── 从 db_connections 表加载连接配置
   │   │   ├── 解密密码，创建 DB 连接池（会话级，用完即焚）
   │   │   ├── 将连接信息注入 System Prompt（让 AI 知道连的是哪个库）
   │   │   └── 挂载场景专属 DB 工具到 tools 集合
   │   └── 如果 scene.toolWhitelist 非空:
   │       └── 过滤通用工具，仅保留白名单中的工具 + 场景专属工具
   └── 无 sceneSlug: 保持现有逻辑（10 个通用工具）

2. 构建合并后的 tools 集合
3. 调用 streamText（其余流程不变）
```

### 4.2 工具定义

#### `db_execute_query` — 通用只读查询

```
description: "在已连接的数据库中执行只读 SQL 查询（仅允许 SELECT/SHOW/DESCRIBE/EXPLAIN）。
             返回结构化的 JSON 结果集。"

parameters: {
  sql: z.string().describe("要执行的只读 SQL 语句")
}

安全约束（后端强制执行）:
- AST 解析或正则拦截：仅允许 SELECT / SHOW / DESCRIBE / EXPLAIN / WITH 开头
- 禁止: INSERT / UPDATE / DELETE / DROP / TRUNCATE / ALTER / CREATE / GRANT / REVOKE
- 结果集行数上限: 1000 行
- 查询超时: 30s
```

#### `db_get_query_plan` — 获取执行计划

```
description: "获取一条 SQL 语句的 EXPLAIN 执行计划（JSON 格式）。
             自动拼接 EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) 前缀。"

parameters: {
  sql: z.string().describe("需要分析的 SQL 语句"),
  analyze: z.boolean().default(true).describe("是否使用 ANALYZE 实际执行并获取真实耗时")
}

后端逻辑:
1. 安全检查：如果 analyze=true 且 SQL 是写操作（UPDATE/DELETE）：
   → 自动包裹为 BEGIN; EXPLAIN ...; ROLLBACK; 事务（安全回滚）
2. 拼接: EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) + sql
3. 返回 JSON 树结构（大模型读 JSON 比文本箭头格式精准）
```

#### `db_get_table_schema` — 获取表结构与索引

```
description: "获取指定表的结构信息，包括字段名、类型、是否可空、默认值，
             以及当前已有的索引名称、索引字段、索引类型。"

parameters: {
  table_name: z.string().describe("要查看的表名（支持 schema.table 格式）")
}

后端逻辑:
- PostgreSQL: 查询 information_schema.columns + pg_indexes
- MySQL: 查询 information_schema.columns + SHOW INDEX FROM
- 返回结构化的表元数据 JSON
```

#### `db_list_slow_queries` — 抓取慢查询

```
description: "从数据库系统视图中获取最近执行最慢的 SQL 查询列表。
             需要数据库已开启慢查询日志或 pg_stat_statements 扩展。"

parameters: {
  limit: z.number().default(10).describe("返回条数，默认 10")
}

后端逻辑:
- PostgreSQL: 查询 pg_stat_statements 视图（按 mean_exec_time 降序）
- MySQL: 查询 mysql.slow_log 表或 performance_schema.events_statements_summary_by_digest
- 如果系统视图不可用，返回友好提示
```

## 六、技术要点

### 6.1 连接池生命周期

- **创建时机**：`POST /api/chat` 收到请求，检测到 `sceneSlug` + `dbConnectionId` 时创建
- **使用范围**：当前 `streamText` 会话的所有工具调用共享同一个连接池
- **释放时机**：`onFinish` 回调中调用 `releasePool(connectionId)`
- **兜底**：设置 `idleTimeoutMillis: 30000`（30 秒无活动自动释放）+ `maxLifetime: 300000`（5 分钟强制回收）

### 6.2 安全约束

| 层级 | 约束 |
|------|------|
| **SQL 语法层** | `db_execute_query` 必须通过 AST/正则校验仅允许只读操作。建议使用 `pg-query-parser` 或手写状态机匹配 `SELECT|SHOW|DESCRIBE|EXPLAIN|WITH` |
| **网络层** | DB 连接仅在后端服务器内网建立，前端不接触任何数据库凭证 |
| **密码存储** | 使用与 API Key 相同的 `encrypt()` / `decrypt()` 函数（`src/lib/auth/crypto.ts`），AES-256-GCM |
| **连接超时** | 测试连接 5s 超时，执行查询 30s 超时，防止僵尸连接 |
| **结果集限制** | `db_execute_query` 最多返回 1000 行，防止大结果集撑爆 Token 上下文 |

### 6.3 npm 依赖

```json
{
  "pg": "^8.13.0",           // PostgreSQL 驱动
  "mysql2": "^3.11.0"        // MySQL 驱动
}
```

> 注意：`pg` 和 `mysql2` 都是纯运行时依赖，不需要原生编译（`mysql2` 有纯 JS 模式）。

### 6.4 错误处理

| 场景 | 处理方式 |
|------|---------|
| DB 连接失败 | 工具返回结构化错误 `{ error: true, message: "连接失败: ..." }`，AI 可据此告知用户 |
| SQL 语法拦截 | 工具返回 `{ error: true, message: "仅允许只读查询 (SELECT/SHOW/...)" }` |
| 查询超时 | 工具返回 `{ error: true, message: "查询超时 (30s)" }`，AI 可建议优化查询条件 |
| `pg_stat_statements` 未安装 | `db_list_slow_queries` 返回友好提示 + 安装命令 |
| 工作空间未选择 | 保持现有逻辑，提示用户先创建/载入工作空间 |

## 十、风险与决策

| 风险 | 决策 |
|------|------|
| **pg/mysql2 驱动原生编译问题** | 使用 `mysql2` 的纯 JS 模式（`mysql2/promise` 默认纯 JS）。PostgreSQL 用 `pg`（有预编译二进制包，Windows 下正常工作） |
| **连接池内存泄漏** | `onFinish` 保证释放 + `idleTimeoutMillis` 兜底 + `releaseAllPools` 在异常路径调用 |
| **AI 违规执行写操作** | 多层防护：(1) System Prompt 明确禁止 (2) `db_execute_query` 后端语法拦截 (3) `db_get_query_plan` 自动包裹 ROLLBACK 事务 |
| **密码加密一致性** | 复用现有 `src/lib/auth/crypto.ts` 中的 `encrypt()` / `decrypt()`，与 API Key 加密完全一致 |
| **多 DB 类型兼容** | `db-pool-manager.ts` 按 `dbType` 分流创建 pg Pool 或 mysql Pool；工具内部按 `dbType` 生成对应 SQL 方言（如 `EXPLAIN` 语法 PG vs MySQL 略有差异） |
| **场景 tool_whitelist 维护** | MVP 阶段 `tool_whitelist` 为 `null`（表示使用全部通用工具 + 场景专属工具）。后期可精确控制 |
| **AI SDK v7 兼容性** | `streamText` 的 `tools` 参数支持动态对象合并，已验证可行（现有代码中 `auraTools` 即为动态对象） |
