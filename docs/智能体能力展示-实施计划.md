# 智能体能力展示页 — 实施计划

> **上游 PRD**：[`docs/智能体能力PRD.md`](智能体能力PRD.md)
> **状态**：📋 待实施
> **创建时间**：2026-07-16

---

## 需求概述

在 Aura 工作台的左侧大菜单中新增入口，打开一个**纯展示页面**，在一个页面中查看系统中所有智能体的**能力**与**工具**。

- **不需要维护功能**（不提供新增/编辑/删除），现阶段只读。
- 页面分两段：
  - **上半部分**：智能体能力一览（按 PRD 四层架构展示）
  - **下半部分**：智能体工具一览（展示已注册的工具列表，后续逐步扩充）

## 一、现状分析

### 1.1 已有的能力定义

PRD 将智能体能力分为四个层次：

| 层次 | 内容 | 来源 |
|------|------|------|
| **L1 SDK 底层能力** | 多模型统一抽象、流式传输、结构化输出、多步工具调用闭环、遥测 | Vercel AI SDK 原生提供 |
| **L2 通用基础能力** | 跨文件读写、自主规划与连续排查、步骤展示、Token 审计 | 使用 SDK `tools` + `maxSteps` + `onChunk` + `onFinish` 组合实现 |
| **L3 高阶能力** | 渐进式实时预览、交互式人机协同、多模态视觉调试 | 榨干 SDK 潜力（`streamObject`、审批挂起、Vision） |
| **L4 外部配套** | 安全沙箱、状态持久化、长期记忆 (pgvector)、配额熔断 | 后台自建，SDK 不提供 |

### 2.3 数据模型

智能体能力数据采用**静态配置**（纯前端），不建数据库表——因为 PRD 定义的能力是产品层面的设计描述，而非用户动态数据。后续若需要维护功能可再升级为 DB。

```typescript
// 能力项
interface CapabilityItem {
  id: string;
  name: string;           // 中文名称
  description: string;    // 一句话描述
  layer: 1 | 2 | 3 | 4;  // 所属层次
  layerName: string;      // 层次名称
  sdkFeature?: string;    // 对应的 SDK 能力名
  status: 'done' | 'wip' | 'planned';  // 实现状态
}

// 工具项
interface ToolItem {
  name: string;           // 工具标识（如 list_directory）
  displayName: string;    // 展示名称（如 目录探测器）
  description: string;    // 功能描述
  category: string;       // 分类：文件发现 | 资产产出 | 沙箱计算 | 外部连接 | 记忆管理
  categoryIcon: string;   // 分类图标
  sourceFile: string;     // 源码文件路径
  registered: boolean;    // 是否已注册到 Agent
}
```

const navItems: NavItem[] = [
  { id: "workbench", label: "智能体工作台", icon: "🤖", path: "/" },

## 七、风险与决策

| 风险 | 决策 |
|------|------|
| **工具数量增长后静态数据维护成本高** | MVP 采用静态配置（10 个工具可控）。当工具超过 30 个时，迁移到方案 B（运行时反射），从 tool 定义中自动提取 description 和 parameters |
| **侧边栏导航未接通其他页面** | 本次将 workbench + capabilities 路由接通即可。knowledge 和 settings 页面暂不存在，点击时保持当前行为（不跳转）或显示"开发中"提示 |
| **通用 Layout 中的 Sidebar 在 /capabilities 页面仍然显示** | 这是期望行为——侧边栏在所有页面中保持一致。Session 中保持 `collapsed` 状态 |
| **能力数据与 PRD 同步** | 能力数据从 PRD 手动提取为静态配置。PRD 更新时需同步修改 `capabilities-data.ts`。未来可考虑从 Markdown 文件自动解析 |
| **客户端模式路由兼容** | 页面纯静态展示，不依赖 API 调用，客户端模式和服务端模式均正常工作 |
| **AI SDK v7 中 useChat 的类型问题** | capabilities 页面不涉及 useChat，无此风险 |
