# 记忆存储 — 实现计划

> 基于 [记忆存储PRD.md](./记忆存储PRD.md) ，对 Aura 工作台进行"全链路可审计"改造。

---

## 一、现状分析

### 已有能力

| 维度 | 现状 |
|------|------|
| **数据库** | PostgreSQL + Drizzle ORM，已有 `users` / `workspaces` / `chatMessages` / `agentKnowledge` / `userModelConfigs` 五张表 |
| **Agent 引擎** | `/api/chat` 使用 `streamText`，支持 9 大工具、多步 ReAct（`maxSteps`）、双模式 Key 解析 |
| **工作空间隔离** | `resolveWorkspaceAwarePath` 基于 `globalThis` 注入上下文，物理路径限定在 `DATA_ROOT/workspaces/user_{id}/{wsId}` |
| **聊天持久化** | `chatMessages` 表按 `sessionId` + `workspaceId` 存储 user/assistant 消息 |
| **会话列表** | `/api/workspaces/chat-sessions` 聚合查询，前端"最近任务"卡片可点击恢复历史 |
| **前端** | 三栏布局（工作空间树 → 预览区 → AI 控制台），`useChat` + `DefaultChatTransport` |

### 缺失能力（PRD 要求）

1. **无 Run 级别追踪** — 没有 `workspace_runs` 表，无法按"一次任务"聚合查看
2. **无 Step 级别追踪** — 工具调用的思考→执行→结果链只存为 JSONB，未结构化为独立步骤
3. **无 Token 用量记录** — `onFinish` 收到 `usage` 但未持久化，用户看不到花费
4. **无工作空间记忆体** — 没有 `workspace_memories` 表或 `.agent_memory.md` 机制
5. **前端无"运行控制台"** — 没有步骤折叠器、用量展示、思考过程可视化

## 二、数据库改造

### 2.1 新增表：`workspace_runs`

每次用户发送消息触发一次 Agent 多步循环，记为一次 Run。

```sql
CREATE TABLE workspace_runs (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    session_id   VARCHAR(255) NOT NULL,          -- 关联 chatMessages.sessionId
    user_prompt  TEXT NOT NULL,                  -- 用户原始输入
    final_response TEXT,                          -- AI 最终文本回复
    prompt_tokens     INTEGER DEFAULT 0,
    completion_tokens INTEGER DEFAULT 0,
    total_tokens      INTEGER DEFAULT 0,
    finish_reason     VARCHAR(50),               -- 'stop' | 'tool-calls' | 'length' | 'error'
    model_name        VARCHAR(100),              -- 实际使用的模型名
    status            VARCHAR(20) DEFAULT 'completed',  -- 'running' | 'completed' | 'error'
    created_at  TIMESTAMPTZ DEFAULT NOW(),
    updated_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_runs_workspace ON workspace_runs(workspace_id, created_at DESC);
CREATE INDEX idx_runs_session  ON workspace_runs(session_id);
```

### 2.2 新增表：`run_steps`

一次 Run 中每个 `streamText` step 的结构化记录。

```sql
CREATE TABLE run_steps (
    id          SERIAL PRIMARY KEY,
    run_id      UUID NOT NULL REFERENCES workspace_runs(id) ON DELETE CASCADE,
    step_number INTEGER NOT NULL,                -- 从 1 开始
    step_type   VARCHAR(50) NOT NULL,            -- 'thought' | 'tool-call' | 'tool-result'
    thought     TEXT,                             -- CoT 思考文本（stepType=thought）
    tool_name   VARCHAR(100),                     -- 工具名称（stepType=tool-call）
    tool_args   JSONB,                            -- 工具调用参数
    tool_result JSONB,                            -- 工具执行返回
    duration_ms INTEGER,                          -- 该步耗时（毫秒）
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_steps_run ON run_steps(run_id, step_number);
```

### 2.3 新增表：`workspace_memories`

工作空间级长期记忆（类似 Claude Code 的 `MEMORY.md`）。

```sql
CREATE TABLE workspace_memories (
    id          SERIAL PRIMARY KEY,
    workspace_id UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    key         VARCHAR(255) NOT NULL,            -- 记忆键（如 'project-stack', 'user-preference'）
    content     TEXT NOT NULL,                    -- 记忆内容（Markdown）
    category    VARCHAR(50) DEFAULT 'general',    -- 'tech-stack' | 'convention' | 'user-pref' | 'fact'
    importance  INTEGER DEFAULT 0,                -- 重要性评分（0-10），用于检索排序
    source_run_id UUID REFERENCES workspace_runs(id) ON DELETE SET NULL,
    created_at  TIMESTAMPTZ DEFAULT NOW(),
    updated_at  TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(workspace_id, key)
);

CREATE INDEX idx_memories_workspace ON workspace_memories(workspace_id);
```

### 2.4 改造策略

- **Drizzle schema 先行**：在 `src/lib/db/schema/index.ts` 中新增三张表的 Drizzle 定义
- **迁移方式**：使用 `drizzle-kit generate` 生成迁移 SQL → `db:migrate` 执行
- **向下兼容**：`chatMessages` 表保持不变，原有会话列表和消息加载功能不受影响

## 三、后端 API 改造

### 3.1 `POST /api/chat` — `onFinish` 增强

**当前问题**：`onFinish` 只写 `chatMessages`，步骤信息仅做 `console.log`。

**改造点**：

```
onFinish 回调流程改造后:
1. 计算 usage（promptTokens / completionTokens / totalTokens / finishReason）
2. INSERT workspace_runs（userPrompt → finalResponse → tokens → modelName → status）
3. FOR EACH step IN steps:
     IF step.stepType === 'thought':
       INSERT run_steps (stepType='thought', thought=step.text)
     FOR EACH toolCall IN step.toolCalls:
       INSERT run_steps (stepType='tool-call', toolName, toolArgs)
       INSERT run_steps (stepType='tool-result', toolResult=对应 result)
4. INSERT chatMessages（user + assistant）— 保持不变
5. 触发记忆提取（见 3.3）
```

### 3.2 新增 `GET /api/workspaces/runs`

查询某工作空间下的所有 Run 列表（分页）。

```
Query: workspaceId, limit(default 20), offset(default 0)
Response: { runs: [{ id, userPrompt, totalTokens, modelName, status, createdAt }] }
```

### 3.3 新增 `GET /api/workspaces/runs/[runId]`

获取单次 Run 的完整详情（含所有 Steps）。

```
Response: {
  run: { id, userPrompt, finalResponse, promptTokens, completionTokens, totalTokens, ... },
  steps: [{ stepNumber, stepType, thought, toolName, toolArgs, toolResult, durationMs }]
}
```

### 3.4 新增 `GET /api/workspaces/memories`

获取工作空间的长期记忆列表。

```
Query: workspaceId, category(optional)
Response: { memories: [{ key, content, category, importance, updatedAt }] }
```

### 3.5 记忆提取逻辑（`onFinish` 后触发）

**方案：用一个小模型调用做后处理**（非实时，异步）。

在 `onFinish` 的最后，提取本次对话中的关键事实：

```
输入：userPrompt + finalResponse + toolResults 摘要
Prompt：「从以上对话中提取需要长期记住的关键信息（技术栈、用户偏好、项目约定等），
        以 JSON 数组返回：[{key, content, category, importance}]。
        如果与已有记忆冲突，标记需要更新。」
输出：upsert workspace_memories
```

> **MVP 简化**：初版可以跳过自动提取，改为在 `writeTextFile` 工具中允许 Agent 直接写 `.meta/memory.md` 文件，服务端每次构建 system prompt 时读取该文件注入。

## 四、前端改造

### 4.1 右侧聊天区 — "运行控制台"面板

在现有 AI 控制台基础上，增加**步骤折叠器（Step Accordion）**。

**交互稿**：

```
┌──────────────────────────────────────────────────┐
│ 🧠 Aura 控制台                    本次: 1.2K tokens │
├──────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────────┐ │
│ │ YOU: 帮我写一个 Python 爬虫                   │ │
│ └──────────────────────────────────────────────┘ │
│ ┌──────────────────────────────────────────────┐ │
│ │ AURA:                                       │ │
│ │ ├─ 💭 思考: 需要先创建工作目录...            │ │
│ │ ├─ 🔧 create_directory("crawler")  ✓ 45ms  │ │
│ │ ├─ 💭 思考: 现在写入爬虫代码...              │ │
│ │ ├─ 🔧 write_text_file("crawler/main.py",...) │ │
│ │ │   ✓ 120ms                                 │ │
│ │ └─ 爬虫已创建完毕，位于 crawler/main.py      │ │
│ └──────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────┤
│ [输入框]                          [发送] [停止]  │
└──────────────────────────────────────────────────┘
```

**实现要点**：

- 读取 AI SDK v7 返回的 `parts` 中的 `tool-invocation` 和 `reasoning`（已有雏形，需增强样式）
- 在消息流中插入 **Run 用量摘要行**（"本次消耗 1,200 tokens · deepseek-chat"）
- 每个步骤可折叠展开，查看完整 tool args / result JSON

### 4.2 新增组件：`RunDetailPanel`

点击某条历史对话后，在预览区展示完整的 Run 详情：

- **摘要卡片**：prompt tokens / completion tokens / 总 tokens / 模型 / 耗时
- **步骤时间线**：垂直时间线展示 thought → tool-call → tool-result
- **记忆变更**：如果本次 Run 修改了工作空间记忆，高亮显示

### 4.3 聊天区 Header 增强

在 AI 控制台头部实时显示当前会话的累计 Token 用量：

```
🧠 AI 控制台 | deepseek-chat | 本次对话 2.4K tokens
```

### 4.4 文件记忆管理 UI（Phase 2）

- 在 WorkspaceTree 的 `.meta/` 目录下展示 `memory.md`
- 允许用户手动编辑记忆文件
- 未来可增加记忆条目的增删改 UI

## 五、System Prompt 记忆注入

### 5.1 改造 `POST /api/chat` 的 system prompt 构建

在 `streamText` 调用前，从数据库加载该工作空间的记忆：

```typescript
const memories = await db.query.workspaceMemories.findMany({
  where: eq(workspaceMemories.workspaceId, workspaceId),
  orderBy: desc(workspaceMemories.importance),
  limit: 20,
});

const memoryContext = memories
  .map(m => `- [${m.category}] ${m.key}: ${m.content}`)
  .join('\n');

systemPrompt += `\n\n【工作空间长期记忆】:\n${memoryContext || '暂无记忆。'}`;
```

### 5.2 Agent 自主更新记忆

新增工具 `update_memory`：

```typescript
updateMemory: tool({
```

## 七、风险与决策

| 风险 | 决策 |
|------|------|
| **Step 数据量增长** | `run_steps` 按 `run_id` 分区（Phase 2），定期清理 90 天前的记录 |
| **记忆自动提取误判** | MVP 先跳过自动提取，仅提供 `update_memory` 工具让 Agent 主动管理 |
| **globalThis 并发问题** | 当前单用户场景可靠；多用户需迁移至 `AsyncLocalStorage`（长远） |
| **AI SDK v7 兼容性** | `onFinish` 中 `steps` 数组结构需实测验证，可能与文档有偏差 |

---

## 八、验收标准

1. 每次对话完成后，`workspace_runs` 和 `run_steps` 中有完整记录
2. 前端聊天区可展开/折叠每个步骤的思考、工具调用和结果
3. 聊天区 Header 实时显示本次对话 Token 消耗
4. 在"最近任务"点击历史会话，预览区展示完整 Run 详情（步骤时间线 + 用量）
5. Agent 可通过 `update_memory` 工具主动写入/更新工作空间记忆
6. 下次对话时，system prompt 自动注入该工作空间的长期记忆
