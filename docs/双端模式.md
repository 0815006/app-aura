# Aura 双端架构设计文档

> 一套代码，两个产物：服务端 (Server) + 客户端 (Client)

---

## 1. 架构概览

```text
                  +-----------------------------------+
                  |      主代码库 (web-aura-next)    |
                  |    Next.js 15 Standalone Mode     |
                  +-----------------------------------+
                                    |
            +-----------------------+-----------------------+
            | 打包方式 A                                      | 打包方式 B (引入 Tauri v2)
            v                                                v
   +-----------------+                              +-----------------+
   |   网页服务器版  |                              |   桌面客户端版  |
   | (独立服务器部署) |                              | (解压即用的 .exe) |
   +-----------------+                              +-----------------+
            ^                                                |
            |                                                |
            +------------- 客户端通过 HTTP API 通信 ------------+

   AURA_MODE=server                                   AURA_MODE=client
   - 直连 DeepSeek API                                - 不直连大模型
   - 操作 DATA_ROOT 目录                               - 调用 Tauri 原生 FS API
   - 持久化到 PostgreSQL                               - 所有 AI 请求转发到服务端
   - 运维重活（定时任务、监控）                          - 读写用户本地文件
```

## 2. 环境变量对照表

| 变量 | 服务端 | 客户端 | 说明 |
|------|--------|--------|------|
| `AURA_MODE` | `server` | `client` | 运行模式 |
| `DATA_ROOT` | `D:\data\aura` | (无效) | 服务端数据根目录 |
| `AURA_SERVER_URL` | (无效) | `http://192.168.1.x:8086` | 客户端指向服务端 |
| `DEEPSEEK_API_KEY` | `sk-xxx` | (不需要) | 仅服务端使用 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | (不需要) | 仅服务端使用 |
| `DATABASE_URL` | `postgresql://...` | (不需要) | 仅服务端使用 |
| `BING_SEARCH_API_KEY` | (可选) | (不需要) | 联网搜索 API Key |

## 3. 核心 Modulestruktur

### 3.1 [`src/lib/env.ts`](../../web-aura-next/src/lib/env.ts) — 环境与路径辅助

- `getAuraMode()` — 读取 `AURA_MODE` 环境变量
- `isServerMode()` / `isClientMode()` — 便捷判断
- `getDataRoot()` — 获取数据根目录（Windows 默认 `D:\data\aura`，Linux 默认 `/data/aura`）
- `resolveSafePath(userPath)` — 路径越权校验 + 解析安全路径（**仅服务端有效**）
- `ensureDataDirs()` — 自动创建 `workspaces/`、`uploads/`、`logs/` 标准子目录
- `getServerUrl()` — 客户端模式下获取服务端 API 地址

### 3.2 [`src/lib/api-client.ts`](../../web-aura-next/src/lib/api-client.ts) — 双端 API 客户端

**服务端模式**：`GET /api/files/list` → 直接请求本地路由  
**客户端模式**：`GET /api/files/list` → 转发到 `http://{AURA_SERVER_URL}/api/files/list`

### 3.3 [`src/lib/tauri/index.ts`](../../web-aura-next/src/lib/tauri/index.ts) — 客户端原生 API 封装

仅在 Tauri 桌面环境中可用的 API 封装：

| 函数 | 对应工具 | 说明 |
|------|---------|------|
| `listDirectory(path)` | `list_directory` | 读用户本地目录 |
| `readFileContent(path)` | `read_file_full` | 读用户本地文件 |
| `writeFileContent(path, content)` | `write_text_file` | 写用户本地文件 |
| `executeShell(cmd, args)` | `execute_python_code` | 执行本地 Shell |
| `openFileDialog()` | — | 原生文件选择器 |
| `openFolderDialog()` | — | 原生目录选择器 |
| `isTauri()` | — | 检测 Tauri 运行环境 |

### 3.5 [`src/app/api/chat/route.ts`](../../web-aura-next/src/app/api/chat/route.ts) — AI 编排入口

- 使用 `@ai-sdk/deepseek` 原生 Provider
- 通过 `streamText` 流式响应
- 注册全部 8 大工具
- `onFinish` 回调中持久化聊天记录到 PostgreSQL
- `maxSteps` 控制最大工具调用步数（防无限循环）

## 4. 快速开始

### 4.1 服务端开发

```bash
# 1. 启动 PostgreSQL
deploy/pgvector-start.bat

# 2. 安装依赖 + 数据库迁移 + 启动开发服务器
deploy/dev-start.bat

# 或手动执行：
cd web-aura-next
npm install
npm run db:migrate
npm run dev    # → http://localhost:8086
```

### 4.2 客户端开发（Tauri）

```bash
cd web-aura-next
npm install
npm run tauri dev    # 启动 Tauri 桌面窗口
```

### 4.3 服务端生产构建

```bash
cd web-aura-next
npm run build
# 输出在 .next/standalone/
```

### 4.4 客户端打包

```bash
cd web-aura-next
npm run tauri build
# 输出 .exe 在 src-tauri/target/release/bundle/
```

## 5. 安全设计

- **服务端路径越权**：所有文件操作通过 `resolveSafePath()` 强制限制在 `DATA_ROOT` 内
- **客户端文件隔离**：客户端通过 Tauri 原生 API 操作本地文件，不经服务端工具逻辑
- **密钥隔离**：`DEEPSEEK_API_KEY` 仅存于服务端 `.env.local`，客户端不持有密钥
- **网络隔离**：生产环境 PostgreSQL 不暴露公网端口
