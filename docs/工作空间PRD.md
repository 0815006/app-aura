# 工作空间（Workspace）需求 PRD

> 版本：v1.3 | 状态：待审核

---

## 1. 双端架构总览

Aura 拆分为 **服务端** 和 **客户端** 两种运行形态，共用同一套代码，通过 `AURA_MODE` 环境变量区分。**双端工作空间完全分离，互不交叉**。

| 维度 | **服务端** (`server`) | **客户端** (`client`) |
|------|----------------------|----------------------|
| 运行方式 | `next start` Standalone，部署在 Windows 服务器 | Tauri 打包 `.exe`，用户双击运行 |
| AI 模型 | 直连 DeepSeek，执行 Agent 工具链 | **不直连大模型**，所有 AI 请求转发到服务端 `/api` |
| 文件读写 | 服务端 `DATA_ROOT`（默认 `D:\data\aura`） | 用户本机文件系统（Tauri 原生 FS API） |
| 工作空间 | `D:\data\aura\workspaces\{uuid}\` | 用户本机任意目录 |
| 持久化 | DB `workspaces` 表 + 服务器磁盘 | **零服务端痕迹**，不存 DB，不存文件副本 |
| 路径校验 | 强制越权校验在 `DATA_ROOT` 内 | 由 `src/lib/tauri/` 操作，不经服务端工具逻辑 |

---

## 2. 服务端数据路径

| 项目 | 路径 |
|------|------|
| 服务部署目录 | `D:\app\aura-server` |
| 数据根目录 (`DATA_ROOT`) | `D:\data\aura\` |

```text
D:\data\aura\
├── workspaces\             # 工作空间根目录（按 UUID 分子目录）
├── uploads\                # 通用上传（后续扩展）
└── ...                     # 其他业务数据目录
```

---

## 3. 服务端工作空间

Agent 操作 `D:\data\aura\workspaces\{uuid}\` 下的文件，每个空间按 UUID 物理隔离。不分输入/输出区，由用户和 Agent 自由创建子目录。

```text
D:\data\aura\workspaces\{uuid}\
├── .meta\                  # 系统隐藏目录（Agent 配置快照）
└── {用户/Agent 自由创建的子目录和文件}...
```

| 操作 | 说明 |
|------|------|
| **新建** | 指定名称 → API 创建目录 + 写入 `workspaces` 行 → 前端激活 |
| **载入（续用）** | 选择已有空间 → 加载历史对话 + 扫描文件清单注入 System Prompt + 重建上下文快照 |
| **退出** | 清空当前会话上下文，回到无空间状态 |
| **删除** | 物理删除目录 + 删除 DB 记录 |

**路径越权校验**：服务端所有文件操作工具，第一行必须校验路径在 `DATA_ROOT` 范围内：
```typescript
const allowedRoot = path.resolve(getDataRoot());
const targetPath = path.resolve(allowedRoot, userPath);
if (!targetPath.startsWith(allowedRoot)) {
  throw new Error('路径越权：禁止访问 DATA_ROOT 以外的文件');
}
```

## 4. 客户端工作空间

- 客户端是**纯 UI 壳**，不运行 Agent 工具逻辑。文件读写统一走 `src/lib/tauri/` 调用 Tauri 原生 FS API。
- 用户通过系统文件选择器指定本地根目录，Agent 指示的操作经服务端 `/api` 推理后，由客户端本地 Tauri API 执行。
- **零服务端痕迹**：不存 DB 记录、不存文件副本、不传文件内容到服务器。数据始终在用户自己机器上。
- 目录结构由用户自由组织，支持嵌套子目录和任意文件。重新打开时需重新选择本地目录。
- 客户端 API 请求通过 `AURA_SERVER_URL` 环境变量自动转发到服务端。

## 5. 页面布局：三栏结构

主工作区采用 **三栏布局**，取代现有两栏 Sidebar + Main 结构：

```
┌──────────────┬────────────────────┬────────────────────┐
│ 工作空间树   │   中间：预览区      │   右侧：AI 聊天区   │
│ (可折叠)     │   (默认等宽)       │   (默认等宽)        │
│              │                    │                    │
│ ├─ 📁 子目录A│  打开文件的        │  与 Agent 对话     │
│ │  ├─ 📄 a   │  内容预览/编辑     │  流式输出          │
│ │  └─ 📄 b   │                    │                    │
│ ├─ 📁 子目录B│                    │                    │
│ └─ 📄 readme │                    │                    │
│              │                    │                    │
│[退出][载入]  │                    │                    │
│[新建]        │                    │                    │
└──────────────┴────────────────────┴────────────────────┘
       ↑               ↑                     ↑
   可折叠/展开   可拖拽分隔线A        可拖拽分隔线B
              （左右调整左侧占比）  （左右调整中间与右侧占比）
```

### 5.1 三栏规格

| 区域 | 默认宽度 | 行为 |
|------|---------|------|
| **左侧：工作空间树** | 240px（展开）/ 0（折叠） | 可折叠；展开时宽度可通过分隔线 A 拖拽调整 |
| **中间：预览区** | 与右侧等宽（各占剩余空间 50%） | 展示选中文件的内容预览/编辑；宽度可通过分隔线 A、B 调整 |
| **右侧：AI 聊天区** | 与中间等宽（各占剩余空间 50%） | Agent 对话交互，流式输出；宽度可通过分隔线 B 调整 |

### 5.2 两条可拖拽分隔线

| 分隔线 | 位置 | 作用 |
|--------|------|------|
| **分隔线 A** | 左侧工作空间树 ↔ 中间预览区之间 | 左右拖拽调整左侧栏宽度 |
| **分隔线 B** | 中间预览区 ↔ 右侧 AI 聊天区之间 | 左右拖拽调整中间与右侧宽度比例 |

- 两条分隔线均支持 **实时拖拽**，拖拽范围受各区域最小宽度限制（≥ 200px）。
- 左侧折叠时，分隔线 A 随左侧栏隐藏；分隔线 B 仍可正常拖拽。
- 左侧展开时，分隔线 A 与 B 均可用，三栏宽度独立调整。

### 5.3 左侧工作空间树操作

- **目录支持折叠/展开**：所有子目录节点均可点击折叠或展开，与文件选择器行为一致。递归嵌套的深层子目录同样支持。
- **面板折叠/展开**：点击折叠按钮收起整个左侧栏，再次点击展开至 240px（或上次拖拽后的宽度）。
- **点击文件**：在中间预览区打开文件内容。
- **右键菜单**：新建文件/文件夹、重命名、删除（服务器端模式）。

### 5.4 底部三个核心按钮

| 按钮 | 行为 |
|------|------|
| **退出工作空间** | 清空当前工作空间上下文，回到无空间状态。客户端版仅清内存，服务器端版下次可重新载入。 |
| **载入服务器端工作空间** | 弹出列表，选择已有的服务器端工作空间并激活。加载其文件树 + 历史对话 + 上下文快照。 |
| **新建服务器端工作空间** | 输入名称 → 调用 API 创建 → `D:\data\aura\workspaces\{uuid}\` 目录生成 + DB 记录写入 → 自动激活。 |

## 6. 数据持久化（仅服务端）

### 6.1 `workspaces` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| name | VARCHAR | 空间名称 |
| context_snapshot | JSONB | 续用上下文（DB 连接串、Prometheus 地址等） |
| status | ENUM | `active` / `archived` |
| create_time | TIMESTAMP | 创建时间 |
| update_time | TIMESTAMP | 最后活跃时间 |

> **注意**：客户端版不写入此表。客户端完全无服务端痕迹。

### 6.2 文件存储

- 服务端文件位于 `D:\data\aura\workspaces\{uuid}\`，工具层所有读写操作必须传入 `workspaceId` 解析路径。
- 客户端文件始终在用户本机，通过 `src/lib/tauri/` 直接操作本地路径，不经过服务端。

---

## 7. 前端交互要点

- **三栏布局**：左侧工作空间树（可折叠） + 中间预览区 + 右侧 AI 聊天区，中间与右侧默认等宽。
- **两条可拖拽分隔线**：左侧↔中间（分隔线 A）、中间↔右侧（分隔线 B）均支持左右拖拽调整宽度，各区域最小 200px。
- `useChat` 请求体固定携带当前 `workspaceId`（客户端模式为 `null`）。
- 点击左侧树文件 → 中间预览区打开内容；右侧 AI 聊天区独立运作不受影响。
- 文件变更后（新建/修改/删除），树形目录实时刷新并高亮新节点。
- **客户端模式**：用户通过系统文件选择器指定本地根目录，前端通过 Tauri API 读取本地目录树渲染。AI 推理在服务端，文件操作在本地执行。

---

> **核心原则**：双端工作空间完全分离、互不交叉。客户端零服务端痕迹，服务端一行 DB + 一个目录。简单、隔离、可续用。
