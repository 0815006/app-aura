## 需求概述

当前智能体能力页面（`/capabilities`）展示了四层 16 项能力 + 10 个通用工具，但存在以下问题：

1. **工具注册表不完整**：已实现的 4 个 DB 工具（`dbExecuteQuery` 等）未注册到 `tool-registry.ts`，在能力页面不可见
2. **5 个场景未展示**：已实现的 5 个专家场景（DB 诊断 + 系统性能 + 需求分析）在能力页面上无体现
3. **能力状态滞后**：部分已完成的能力仍标记为 `wip`（如长期记忆）、部分待实施能力（如配额熔断）可直接低成本实现
4. **底座工具缺失**：缺少一个通用的 Shell 命令执行工具（`execute_command`），目前只能执行 Python

> ⚠️ 模板渲染类复杂样式后端工具（`render_docx_template` 等）不在本次范围，已搁置。

### Phase 2：动态配额熔断（后端安全层）

#### 2.1 新增表：`workspace_quotas`（可选，MVP 用内存方案）

MVP 阶段不新增表，直接在 `/api/chat` 中实现轻量配额检查：

```typescript
// 每日 Token 配额常量（可通过环境变量覆盖）
const DAILY_TOKEN_LIMIT = parseInt(process.env.AURA_DAILY_TOKEN_LIMIT ?? "500000", 10);
const MAX_STEPS_HARD = 20; // maxSteps 硬上限，前端传入超过此值则降级
```

**文件**：[chat/route.ts](../web-aura-next/src/lib/agent/tool-registry.ts) → 实际是 `src/app/api/chat/route.ts`

在 `POST /api/chat` 处理流程中增加：

1. **maxSteps 硬限制**（第 167 行附近）：`const maxSteps = Math.min(body.maxSteps ?? 15, MAX_STEPS_HARD);`
2. **每日 Token 消耗检查**（在 `streamText` 调用前）：
   ```typescript
   // 查询当前工作空间今日 Token 消耗
   const todayStart = new Date(); todayStart.setHours(0,0,0,0);
   const todayUsage = await db.query.workspaceRuns.findMany({
     where: and(eq(workspaceRuns.workspaceId, workspaceId), gte(workspaceRuns.createTime, todayStart)),
     columns: { totalTokens: true },
   });
   const todayTotal = todayUsage.reduce((sum, r) => sum + (r.totalTokens ?? 0), 0);
   if (todayTotal >= DAILY_TOKEN_LIMIT) {
     return Response.json({ code: 429, message: `今日 Token 配额已用尽（${DAILY_TOKEN_LIMIT.toLocaleString()}），请明天再试` }, { status: 429 });
   }
   ```
3. **熔断提示注入 System Prompt**（Token 接近上限时提醒 AI 精简回复）
